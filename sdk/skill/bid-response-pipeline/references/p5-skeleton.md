## 第二部分：四条铁律

### ① 章节骨架 100% 来自【详细评审表的评审项目列】——不是投标人发明的

三份标书的章标题与评分表评审项目**逐字对应**。做法：

1. P2 抽条款时把评分表「评审项目」列单独列出（scoring 类的行标题，不是分值）；
2. P3 建大纲时**一章对一评审项目，一节对一评分细则条目**，顺序按评分表原序；
3. 不允许合并两个评审项目为一章（合并 = 评审找不到对应章节 = 系统性丢分），
   也不允许自创加分项章节（评审表没有的，最多作为该章内的一节）。

反例：把「供货方案 + 安装运输方案」合成「供货与实施方案」——评审表两项、正文
一章，评审按项打分时只能按低分计。

### ② 标题即题目——电信项目把评分细则直接写进标题

```
第三节 承诺维修服务响应时间：响应时间30分钟内
第一节 在项目实施所在地设立相应的技术支持及售后服务机构
第二节 有完整的服务质量自检措施、整改保障措施
```

这类标题是**从评分表原样搬来的判分条件**。评审按标题逐条打分，所以：

- 标题里的**每一个限定词都必须正面回应**：「30分钟内」要写清计时起点（接到
  报修电话？工单派发？到场？）、超时处置、如何证明（工单模板/系统截图/考核
  承诺）；「项目实施所在地」要给具体城市、具体地址、房屋产权或租赁凭证、常驻
  人数；「完整的」「相应的」这类形容词对应的是**清单的完备性**，要给全量清单；
- **不允许改标题措辞**（改了就与评审表对不上号）；标题读起来不像话也照抄，
  最多在正文第一句把它翻译成人话；
- 标题含承诺词（承诺/保证/确保/完全满足）时，正文同句必须带引用或可核验的
  量化指标——否则 P6 记 `unanchored_claims`。

### ③ 每节 3-16 万字，单节平均 5 万字——必须分批写

实测分布（A 项目 19 节）：最小 3.0 万字（第三节 人力安排计划），最大 15.7 万字
（第五章第四节 定期巡检方案），节均 ≈ 5.0 万字（95.2 万 / 19）。

- 15.7 万字的一节 = **40 批 × 4000 字**（见 SKILL.md §篇幅纪律）；
- 3 万字的一节 = 8 批；
- 单节超过 4000 字就别指望一次生成：写完一批 →
  `append_section_segment`（提交**本批段文**，前批不丢）→
  读 `remaining_chars` / `remaining_segments` → 写下一批 → `save_version`。
  ⚠ 不要用 `draft_response_section` 分批提交——它是整稿替换，会静默丢前批
  （#254 真实事故：九次重提越写越短）；
- 分批不按字数硬切，按**节内小节**切：一个三级标题一批（约 3000-4000 字），
  天然避免跨批重复。

### ④ 大类章节高度同构——「五件套」

```
供货/服务方案 → 质量保证 → 安装运输 → 售后服务 → 应急方案
```

B、C 两份是完整五件套；A（服务类）把「安装运输」并入服务方案、另立保密章节，
其余四件不变。差异只在**小节标题的行业措辞**：

| 大类 | 设备供货类（B/C） | 网络运维服务类（A） | 水利工程类（推断） |
|---|---|---|---|
| 方案 | 供货方案 / 整体供货方案 | 服务方案 | 施工组织设计 |
| 质量 | 质量保证措施方案 | 质量保证 | 质量管理体系 |
| 运输安装 | 安装运输方案 | （并入服务方案） | 施工方案 / 设备安装 |
| 售后 | 售后服务方案 | 服务承诺 | 运行维护 / 保修服务 |
| 应急 | 应急方案 | 应急方案 | 度汛方案 / 抢险预案 |
| 专项 | 培训方案 | 保密工作 | 水库除险加固 / 安全生产 |

用法：**写水利项目就写「水库除险」，写电信项目就写「网络运维」，但骨架的五段式
不变**。评审看的是「有没有这一段」，不是「这段叫什么名字」。

## 第三部分：六类章节的写作要点

> 每类三块：必须覆盖的要点（从真实标题倒推）/ 常见失分点 / 字数分配建议。
> 字数建议以「本章在评分表中的分值占比」为基准，参照三份标书的实测分布。

### 1. 供货 / 服务方案

#### 必须覆盖的要点

- **时间安排**：总工期倒排表 → 里程碑 → 每阶段起止日 → 与合同工期的对应；
  给甘特图或节点表，用「T+N 日」相对时间，不写「尽快」「及时」；
- **供货计划（范围与数量）**：分批次、每批数量、到货点、随批资料；与工程量
  清单/BOM 逐项对应，各批数量之和等于清单总数；
- **人员配置**：项目班子组织图 → 岗位 → 姓名/职称/证书编号 → 到岗时间 →
  投入率（%）；项目经理、技术负责人、安全员是必设三岗；
- **供货渠道**：制造商授权 → 一级代理 → 本项目专项授权书 → 原厂质保承诺，
  逐级给文件编号；进口件给报关/原产地承诺；
- **供货方式**：送货上门 / 甲方自提 / 第三方物流，写明运输责任分界点（到货
  验收前风险由谁承担）、卸货义务、随货单据清单；
- **服务方案的行业变体**（A 项目）：整体服务方案（建设期+运维期分开写）、服务
  人员管理规范（考勤/着装/行为/保密/考核）、人力投入计划（按月 × 岗位人数矩阵）、
  服务进度保障、服务时间节点安排（7×24 值班表）。

#### 常见失分点

- 只写「我方承诺按合同工期供货」，不给倒排表、不给具体日期——评审判「无实质性
  响应」；
- 人员表只列姓名不列证书，或证书编号与资格部分对不上（跨章不一致是高频扣分点，
  P6 会做确定性比对）；
- 供货渠道通篇是自己公司介绍，没有制造商授权书编号；
- 时间节点与应急方案、售后响应时间互相矛盾（承诺 30 分钟响应，却写「每月巡检
  一次」——两处时间基准要一致）；
- 「供货方式」写成商务条款复述，没写风险分界点。

#### 字数分配建议

- 设备供货类（B/C 口径）：整章 2.4-10 万字，4-7 节，节均 0.9-2.4 万字；
  时间安排 + 供货计划合计 ≥ 40%，人员配置 ≥ 20%；
- 服务类（A 口径）：整章 20 万字级，5 节，节均 3.0-5.5 万字；「整体方案」只占
  20%，其余 80% 给管理规范/人力/进度/节点（评审看的是可执行性）；
- 单节下限：任何一节不少于 8000 字——低于 8000 字的节在评审眼里是「没写」。

### 2. 质量保证

#### 必须覆盖的要点

- **体系**：ISO 9001 证书编号 + 有效期 + 覆盖范围含本项目标的；体系文件目录；
  组织架构与质量责任人；
- **目标**：可量化指标（一次验收合格率 100%、返修率 ≤x%、投诉响应 ≤x 小时），
  每项指标配考核办法与奖惩；
- **人员职责**：质量负责人、质检员、班组的职责矩阵（RACI）；
- **源头控制**（C 项目「生产或进货时质量保证措施」）：供应商评审、进货检验
  （抽检比例/判定标准/不合格处置）、出厂检验报告；
- **过程控制**：关键工序清单 → 控制点 → 检查方法 → 记录表单编号；
- **配送/交付过程质量**：运输防护、途中抽检、到货复检；
- **验收保障制度**：验收组织、验收依据（国标/行标/合同技术条款）、验收流程、
  不合格品处置闭环；
- **自检与整改**（A 项目）：自检频次、自检表单、问题分级、整改责任人与时限、
  复查销项；
- **风险控制**：风险清单（识别/评估/应对/责任人）、质量事故应急预案；
- **质量反馈与退换货**（B 项目）：反馈方案写 发现渠道→反馈时限→处理时限→责任
  划分→复检；退换货写 退换条件→流程→运费承担→时限。

#### 常见失分点

- 通篇「我们将严格控制质量」，没有一个可度量指标、一个表单编号；
- 引用了 ISO 9001 却没给证书编号/有效期，或证书范围不含本项目内容；
- 质量目标写了，正文没有任何考核办法佐证，被评审判为空头承诺；
- 「过程控制」只列工序名，不给控制点参数、检查方法、记录表；
- 质量章节的检验节点与供货方案的到货时间对不上；
- 只写体系不写「谁在什么时候检查什么」（缺 RACI 矩阵）。

#### 字数分配建议

- 体系 + 目标 + 职责：20%-25%；过程控制 + 源头控制：30%-35%；验收 + 自检整改：
  25%-30%（A 项目把「服务质量自检措施、整改保障措施」单独做到 6.7 万字，占该章
  26%，说明评审很吃这一块）；风险控制 10%-15%；
- 整章区间：C 项目 7 节约 4-6 万字（节均 6000-8000 字）；A 项目 4 节 25.7 万字
  （3.1 + 6.7 + 10.2 + 15.7）；**按评分占比定，不按项目大小定**。

### 3. 安装运输

#### 必须覆盖的要点

- **包装**：包装材料与等级（木箱/防潮/防震）、内衬与固定方式、标识（唛头/向上/
  易碎）、随机文件袋清单；引用 GB/T 包装标准；
- **装卸**：装卸设备型号吨位、吊点与吊装方案、人员资质（起重工证）、作业安全
  措施、超限大件专项方案；
- **运输**：运输方式、车辆配置（车型/数量/GPS）、路线规划与备选路线、限高限重
  核查、押运与货运险保单；
- **紧急运输**：加急通道、专车直达、空运兜底、响应时限、费用承担；
- **安装**：安装流程图 → 分项工艺 → 关键参数（垂直度/扭矩/间隙）→ 质量检验点
  → 与土建/其他标段的接口协调；
- **调试**：单机调试 → 联动调试 → 试运行 → 性能测试，每步给判定标准与记录表；
- **冬雨季防护**（C 项目）：冬季施工措施（温度阈值/防冻/养护）、雨季措施
  （排水/防潮/停工恢复）、季节性材料储备、劳动保护。

#### 常见失分点

- 包装只写「采用木箱包装，确保运输安全」——没有材料规格、没有标准依据；
- 装卸方案写的设备吨位小于实际最重件（可被反查工程量清单，属硬伤）；
- 运输路线不写，或写「由我方物流部门安排」——评审要看可核查的路线与车辆；
- 安装方案抄设备说明书，没有本项目的质量检验点；
- 缺调试与试运行，安装完就收尾（调试是独立评分点）；
- 冬雨季措施写成通稿，与项目所在气候区不匹配（南方项目写防冻不写防台）。

#### 字数分配建议

- 包装 15% / 装卸 15% / 运输 20% / 紧急运输 10% / 安装 25% / 调试 10% / 季节性
  防护 5%；
- 整章区间：C 项目 7 节约 3-5 万字；B 项目 4 节约 3-4 万字；
- 安装 + 调试合计不少于整章 35%——这两节才体现履约能力，别把字数花在包装上。

### 4. 售后服务

#### 必须覆盖的要点

- **响应时间**：分级（一般/紧急/重大）→ 响应/到场/修复三段时限 → 计时起点定义
  → 超时违约金与补偿；30 分钟级响应要给制度保障（值班表、驻点、前置备件仓），
  不是一句承诺；
- **服务团队与人员配置**：人数、岗位、资质证书、驻点分布、7×24 值班排班表、
  人员稳定性承诺；
- **服务保障内容**：服务范围清单（巡检/保养/维修/技术支持/软件升级）、服务方式
  （电话/远程/现场）、服务频次、服务记录与回访；
- **服务管理体系**：流程（受理→派工→处理→回访→归档）、工单系统、服务 KPI 与
  考核、满意度调查；
- **便捷性**（B 项目）：服务网点分布与半径覆盖、就近工程师、备用通道；
- **备品配件**：备件清单（型号/数量/单价）、前置仓位置、以旧换新或寄售机制、
  停产件替代方案；
- **维修承诺**（C 项目）：质保期、质保范围与除外条款、维修时限、返修件处理；
- **补偿措施**（B 项目「对采购人造成损失的补偿措施」）：损失认定方式、赔付标准
  与上限、先行赔付、保险兜底——必须给数字，否则是空话。

#### 常见失分点

- 「7×24 小时响应，2 小时内到场」写了但**没有支撑**（无驻点、无值班表、无备件
  仓）——评审直接按不可信处理；
- 响应时限与应急方案、服务承诺章节的数字不一致（三处数字打架是最常见的跨章
  扣分）；
- 备品配件只写「常用备件充足」，没有清单和数量；
- 补偿措施不敢写数字（怕担责），结果该评分点零分——写清上限与计算方式反而更
  可信；
- 售后团队名单与资格文件、社保证明对不上；
- 缺「服务记录/回访/满意度」闭环，评审认为无法考核。

#### 字数分配建议

- 响应时间 10%-15% / 团队配置 20% / 保障内容 25% / 管理体系 15% / 备品备件 15%
  / 承诺与补偿 10%-15%；
- 整章区间：B 项目 5 节约 8-12 万字（节均 1.6-2.4 万字）；C 项目 4 节约 4-6 万字；
- 服务类参考 A 项目：把「设立售后服务机构」单独做到 6.9 万字——机构落地（地址/
  人数/场地凭证）是承诺能否被信的分水岭。

### 5. 应急方案

#### 必须覆盖的要点

- **人员安排**：应急组织架构（总指挥/现场组/保障组/联络组）→ 名单与电话 →
  集结时间 → 后备人员池；用表不用段落；
- **应急处理预案**：风险场景清单（设备故障/供货中断/质量事故/安全事故/自然灾害）
  → 每场景一张预案卡：触发条件 → 分级 → 处置流程（步骤化）→ 资源 → 恢复时限
  → 复盘；
- **紧急供货**（B 项目）：触发阈值（库存低于 x / 停产 / 需求突增）、备用供应商
  名单、加急运力、时限承诺；
- **突发交通事故应急**（B 项目）：上报 → 现场处置 → 货物保全与转运 → 备用运力
  调派 → 对采购人工期的补救承诺；
- **故障补救**（A/B 共有「对备品配件、设备发生故障后的补救措施」）：备件到位
  时限 → 替代设备先行 → 修复 → 责任界定；
- **联系方式**（A 项目单列 5.1 万字）：固定联系人表（姓名/职务/手机/邮箱/值班
  电话）→ 分级联络路径 → 备用通讯方式 → 与采购人的联络机制。

#### 常见失分点

- 预案写成「成立领导小组，立即启动预案」的通稿，没有触发条件、没有分级、没有
  步骤；
- 联系表里是总机或分公司座机，没有 24 小时可接通的手机号；
- 应急人员与项目班子不是同一批人，或同一人出现在多个不相容岗位；
- 应急响应时限比常规售后响应时限还长（逻辑倒挂）；
- 预案不覆盖本项目真实风险（水利项目不写度汛、运输项目不写交通事故）；
- 缺「复盘与改进」，预案成了静态文件。

#### 字数分配建议

- 组织与人员 20% / 场景预案（逐场景）45% / 资源保障（备件/运力/替代设备）20% /
  联络机制 10% / 复盘改进 5%；
- 整章区间：A 项目 3 节 14.0 万字（人员 3.9 + 预案 5.0 + 联系方式 5.1）——服务类
  可以把「人员安排」和「联系方式」各做成一节；设备供货类（B）3 节约 3-5 万字；
- 单场景预案卡不少于 1500 字，否则写不完整流程。

### 6. 培训方案

#### 必须覆盖的要点

- **培训计划**：培训对象与人数 → 课程表（课目 × 课时 × 时间 × 地点）→ 培训方式
  （集中/现场/远程/跟班）→ 考核方式（笔试/实操/持证）→ 不合格补训；给完整
  课表，不写「由讲师根据情况安排」；
- **讲师配置**：专职讲师姓名、职称、从业年限、授课科目、证书；外聘讲师给合作
  协议；讲师与交付团队的关系说清；
- **培训内容重点及难点**：分对象分层（管理层/操作层/维护层）的课目清单 → 每门课
  的重点 → 本项目特有难点（新设备、新系统、跨部门协同）→ 针对性教学手段；
- **培训保障**：教材、实训场地、设备、考核题库、培训档案与签到表模板；
- **效果评估**：满意度、掌握率、上岗合格率，与后续运维的衔接。

#### 常见失分点

- 只写「我方将提供全面培训」，没有课时、没有课表、没有讲师；
- 讲师是「资深工程师」这种描述，无姓名无资质；
- 课程表是通用办公软件培训，与本项目设备/系统无关；
- 「重点难点」写成套话（「重点是熟练掌握，难点是理解原理」）——没有具体知识点；
- 培训时长与项目实施工期冲突（培训排在交付后，却承诺交付即上岗）；
- 缺考核与补训机制，评审认为培训无法落地。

#### 字数分配建议

- 培训计划 40% / 讲师配置 20% / 内容重点难点 30% / 保障与评估 10%；
- 整章区间：C 项目 3 节约 1.5-2.5 万字（节均 6000-8000 字）——**培训是最容易被
  写短的一章，但一旦成为独立评分项就必须单独成章**；
- 若培训不是独立评分项，压缩为供货/售后章节中的一节，5000-8000 字即可。

## 用法（P5 阶段的三个动作）

1. **P3 建纲后**：拿本项目【详细评审表】的评审项目列与本页三份骨架对表——评审
   项目落在五件套的哪一件，该类就套对应小节结构，只替换行业措辞；
2. **P5 起草前**：按 `quota.target_chars` 找同类节的实测篇幅，确认分批数
   （字数 / 4000 = 批数），并把该类「必须覆盖的要点」做成节内三级标题；
3. **P5 自检时**：逐条对照该类「常见失分点」，命中即改——这是评审扣分的高频
   位置，比文采重要。

> 骨架是**下限**不是上限：评审表要求但本页没列的评分点，以评审表为准补进去。
> 本页只回答「真实的中标文件长什么样」，不替代招标文件。
