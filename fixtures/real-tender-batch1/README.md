## 文件名纪律（重要）

**入库时保留 zip 内的原始文件名，不重命名。**

```
原始：超融合集群招标文件（[230001]GCZX[GK]2026000720261023001）.pdf
不用：tender.pdf
```

原因：文件名里带**项目名称和项目编号**。无上下文的 Agent 第一反应会从文件名读这两项。
改名会剥夺这条路径，逼它去 PDF 里找——**改变了测试条件，测不出真实难点**。

## 输入形态纪律

黑盒考验时给子代理的是**解压后的 PDF（原始文件名）**，不是 zip。

```
用户实际拿到：xxx-文件集.zip
考验时给的是：xxx招标文件（[编号]）.pdf   ← 解压后、保持原名
```

## 共同特征

```
同一平台导出（黑龙江政府采购平台）
CJK 占比 0.661 - 0.683（文本层干净，无乱码）
```

## ⚠️ 过拟合风险（必读）

**这 5 份是同一套模板的 5 个填值实例。**

量化结果：

```
章节标题 Jaccard 相似度：
  college-ai    x danqing        = 0.96
  college-ai    x wenming        = 0.96
  hc-cluster    x hq-dev-procure = 0.95
  （两组之间 0.62，但组内几乎相同）

5 份共有的章节标题：71 个
全部章节标题并集：121 个
→ 58.7% 的章节标题完全相同

各题「独有」章节：每份只有 2 条，且都是「采购人：xxx」「采购代理机构：xxx」
```

### 为什么有重合

全部来自**黑龙江政府采购平台统一导出**——章节骨架、格式件清单、
评分表结构、术语全部是同一套。真正的差异只在：

```
采购人名称 / 项目内容 / ★条款数量 / 金额
```

### 这影响什么

**不能用这批数据得出「引擎通用」的结论。**

```
风险：
  抽取规则会对固定标题（「投标人须知前附表」「第三章采购需求」）过拟合
  格式件识别会对固定名称（「黑龙江省政府采购供应商资格承诺函」）过拟合
  评分表解析会对黑龙江这一套评审项结构过拟合

后果：
  遇到别省/别平台的招标文件可能全线崩溃，而我们不知道
```

### 使用纪律

1. **所有结论标注适用范围**：「基于黑龙江政采平台 5 份样本，对其它省份未验证」
2. **发现硬编码固定字符串**→ 单独开「过拟合缺陷」issue
3. **判断标准**：

```
用结构特征（「第X章」+「评审内容/分值」表头）  ✓
用字面字符串（完整的省名+标题）              ✗
```

### 已登记的缺口

```
当前：只有黑龙江政采平台一种格式
需要：其它省份 / 其它平台 / 不同版式的招标文件做对照组
建议：至少再加 2-3 份异源样本，才能说「引擎通用」
```
