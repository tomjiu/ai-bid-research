-8.3pp。A2（编号叠加）对 docx 面是**条款号体系性污染（99.9%）**，直接打穿
合规矩阵行号、补遗条款配对、引用锚三个下游面——**B3 前必须修**。

## 2. 挂在标题下的条款（父子关系量化）

「挂标题下」= 类别判定依赖章节上下文的条款。V0→V1 配对（4,774 对按
(source_file, excerpt) 配对）：

- **类别翻转 169 条**（3.5%）：编号条款的类别由 `category_for(章, 节)` 改判
  （评标办法章→评分项、技术章→技术参数、须知+资格节→资格条件等），标题丢失后
  全部落「其他」兜底。
- **评分项 438→221**：其中 ~165 条编号条款翻转为「其他」，**52 条无编号评分
  细则行彻底消失**（`re_score_line` 通道要求 `chapter.contains("评标办法")` 门，
  章节上下文空则通道死；评分算法行 `评标基准价/下浮率K` 免章门故存活）。
- 短语通道免疫实证：否决项 71→72、资格条件 164→160（强否决/资格面短语行
  不依赖标题，仅 4 条经「须知+资格节」上下文的资格条目翻转）。
- 类别分布对照（V0 → V1）：其他 4027→4195、评分项 438→221、资格条件 164→160、
  否决项 71→72、技术参数 121→121、商务要求 3→3、格式要求 4→4。

## 4. A2 编号污染的影响面（V2）

V2 按引擎 TR-2D 实测签名构造（`corrupt_a2`："1.1"→"11.1"——Word 自动编号与
文本可见编号叠加；引擎读面复现证据：word-complex.docx 读回「11.1 表格」，
`artifacts/engine-probe/report.json`）。

- **条款号污染：docx 源 1809/1810 = 99.9%**（PDF 源 3018 条免疫——文本层编号
  烤死在文本里，不经引擎导入链）。
- 类别/召回零变化（污染只改编号前缀，不打断短语通道）——**危害不在抽取层，
  在下游三个面**：
  1. **合规矩阵行号**：REQ.clause_no 全错 → 矩阵条目与招标文件对不上号；
  2. **补遗条款配对**：V2 影响面引擎按 clause_no 匹配变更条款（V2 七断言组
     R1 语义）——编号污染使补遗配对全盘失效（这是 M2 的地基）；
  3. **引用锚回查**：判分对齐器 clause_no 双因子之一失效（单因子降级）。
- **结论：A2 是 B3 的硬前置**——引擎导入链不修编号叠加，docx 主文件的解析
  结果对下游不可用（PDF 件不受影响，但 telecom 真实 docx 7 件全在污染面内）。

## 5. 对引擎侧 A1/A2 排期的反馈（本分析的用途）

1. **A2 优先级应高于 A1**：A1 当前形态（heading 属性丢失、文本保留）对标书
   抽取**零影响**（本文 §0/§2 实证——标书自建上下文免疫）；A2 是 99.9% 条款号
   污染，打穿 M2 地基。
2. **A1 的真实价值面**在引擎结构输出（目录 G1/大纲/章节树/证据按章挂接），
   不在标书抽取层；若引擎侧需要 A1 验收的标书面证据，用本文 V1 极端面数据
   （评分项 -50.2%、GT 召回 -4.1pp、类别翻转 169 条）作为「标题文本若丢」的
   上界损失，用 §0 V1≠A1 现状的区别说明当前形态无害。
3. **A3/A4（行内 marks/G2 导出链）不在本实验面**（导出面另由 V1-c 交付样本
   回归覆盖），但同属标书导出依赖——与 A2 一起构成 B3 前置集合。

## 6. 复现协议

```bash
# 1) 三变体实验（Rust harness，真跑 extract_requirements）
cd scripts/title_impact && cargo build --release
./target/release/title-impact <repo_root> artifacts/title-impact/experiment.json
# 2) GT 召回对照（Python 判分，对齐逻辑同 real_eval_score.py）
python3 scripts/title_impact_score.py
# 3) 摘要入仓（experiment.json 本地保留、.gitignore 不入库；结论落 summary.json）
python3 scripts/title_impact_summary.py
```

确定性：实验输出无时间戳/无随机（BTreeMap 序）；summary.json 双跑字节一致
（sha256 复现）；摘要脚本对 V0→V1 类别翻转计数带**口径一致性断言**（与 harness
`pair()` 同源逐条配对，本地推导 ≠ harness 计数即停止）；`experiment.json` 三 dump 的
04号子集与 `artifacts/real-eval/extract/requirements.json` **内容级逐条一致**
（仅全局序号偏移，已核验）——V0 即现行抽取器的真实输出。
