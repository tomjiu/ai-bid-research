## 一、候选池的构造与盲区根源

原候选池 = **20 词表（contains）+ 37 否决句式模式**，对**单个块独立匹配**（`scripts/veto_gt/src/bin/dump.rs`）。
这个构造有一个结构性缺陷：**汉语招投标文书的否决条款大量以「父条款 + 编号子项」成组出现，触发词（否决/不得/串通/无效）只在父条款，子项本身无任何词表词**——逐块独立匹配天然漏掉全部子项。

### 召回为何不降反升（issue 要求如实说明）

issue 预判「新增 true 拉低召回」——实际 L1/L2 双升。原因：+540 true 中约 483 条来自 FP 转正
（引擎本来就抽到了、只因 GT 漏标被算 FP），这些条目同时抬高分子与分母且分子增益更大；
纯召回侧新增（引擎也漏的）约 57 条，被分母稀释后 L1 仍净升。**这不是粉饰——FP→TP 转正
恰恰是「修尺子」的本义：把被冤枉的抽取平反。**

### DOCX L1 微降 0.33pp 说明

DOCX 组 true 759→1,173（+414，分母 +55%），covered 711→1,095。微降来自少量 S1/S4 新 true
（如兜底子项「（14）法律法规规定的其他情形」）引擎尚未抽取——真实的召回缺口，已在 missed 清单。
